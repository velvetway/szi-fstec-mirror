# szi-fstec-mirror

Зеркало **Государственного реестра сертифицированных средств защиты информации** ФСТЭК России: исходная выгрузка + готовая SQLite-база с FTS5-поиском, распознанным типом средства, классом защиты и статусом сертификата.

Источник: <https://reestr.fstec.ru/reg3> (раздел «Реестры» ФСТЭК России).

## Зачем

Официальный реестр публикуется как таблица, пригодная для чтения человеком, но не для программной работы: срок действия смешан с текстовыми состояниями, тип средства нигде не выделен, класс защиты спрятан внутри строки с перечнем документов. Плюс сайт отдаёт `403` без браузерного `User-Agent` и использует сертификат УЦ Минцифры, которого нет в системных хранилищах.

Это зеркало решает обе задачи: данные лежат готовыми к запросу, забрать их можно обычным `curl` с `raw.githubusercontent.com`.

## Данные

## Схема

### `certificates`

| Поле | Смысл |
|---|---|
| `certificate_number` | номер сертификата |
| `registered_at` | дата внесения в реестр |
| `valid_until` | срок действия (ISO) или `NULL` для бессрочных |
| `validity_kind` | `dated` \| `perpetual` \| `suspended` \| `unknown` |
| `is_active` | действует ли сертификат на дату сборки |
| `name` | наименование средства (шифр) |
| `requirements` | документы, требованиям которых соответствует средство |
| `tool_type`, `tool_type_name` | распознанный тип средства |
| `protection_class` | класс защиты 1–6, меньше — строже |
| `ndv_level` | уровень контроля отсутствия НДВ |
| `applicant`, `applicant_details` | заявитель и его реквизиты |
| `laboratory`, `certification_body` | испытательная лаборатория, орган по сертификации |
| `support_until` | окончание технической поддержки со слов заявителя |

### `certificate_controls`

Связь сертификата с методами противодействия из модели ПТСЗИ (`A`, `FW`, `HP`, `DZ`, `IDS`, `AD`, `R`, `L`, `TE`, `DS`, `DD`).

Средство нередко сертифицировано сразу по нескольким профилям — Dallas Lock, например, проходит и как СЗИ от НСД, и как СОВ, и как МЭ. Поэтому связь многие-ко-многим: одно средство закрывает несколько методов.

## Покрытие методов ПТСЗИ

Действующие сертификаты:

| Метод | Сертификатов | Заявителей |
|---|---|---|
| `AD` системы администрирования | 106 | 72 |
| `FW` межсетевой экран | 62 | 35 |
| `DZ` демилитаризованная зона | 62 | 35 |
| `L` защита от НСД | 46 | 29 |
| `IDS` обнаружение вторжений | 44 | 30 |
| `A` антивирус | 25 | 7 |
| `TE` шифрование трафика | 2 | 1 |
| `R` резервное копирование | 2 | 2 |
| `DS` цифровая подпись | 2 | 1 |
| `HP` honeypot | — | — |
| `DD` DDoS-фильтры | — | — |

Три пробела объяснимы и не являются дефектом сборки:

- **`TE` и `DS`** — криптографические средства сертифицирует ФСБ России, а не ФСТЭК. Эти два метода закрываются другим реестром.
- **`HP` и `DD`** — у ФСТЭК нет отдельных профилей защиты для honeypot и средств подавления DDoS, поэтому такие продукты в реестре как класс не выделены.

## Цены

Реестр ФСТЭК цен не содержит и содержать не может: это перечень сертификатов, а не прайс-лист. Цены собраны отдельно из открытых источников и лежат в `data/prices.csv`, откуда `scripts/merge_prices.py` подмешивает их в базу **отдельным шагом после сборки** — иначе автоматическая пересборка из реестра их бы затирала.

Срез на 2026-08-19: **133 продукта от 69 вендоров**, из них **31 с ценой** и 102 без. 175 связей с позициями реестра.

Покрытие ценами по методам ПТСЗИ: `L` — 16 средств от 9 вендоров, `FW`/`DZ` — 13 от 8, `A` — 13 от 3, `AD` — 12 от 9, `IDS` — 8 от 8, `R` — 1.

Каждая цена обязана нести источник. Строка с ценой, но без `source_url` отбрасывается сборщиком: цифра, происхождение которой нечем подтвердить, хуже её отсутствия.

| Поле | Смысл |
|---|---|
| `price_min` / `price_max` | диапазон в рублях — стоимость зависит от объёма закупки и состава пакета |
| `license_model` | `per_node` \| `per_server` \| `perpetual` \| `yearly` \| `appliance` \| `unknown` |
| `source_url` | страница, где цена опубликована |
| `source_type` | `vendor` \| `reseller` \| `procurement` \| `NOT_FOUND` |
| `collected_at` | дата сбора |
| `note` | за какую конфигурацию цена либо причина отсутствия |

Почему у трёх четвертей позиций цены нет — и это не пробел сбора.

Публичный прайс существует только там, где у продукта **фиксированная единица лицензирования**: рабочее место, коробка, соединение, шасси. Корпоративные СЗИ — NGFW, SIEM, DLP, NDR, WAF — лицензируются по метрикам нагрузки: RPS, EPS, объём трафика, сокеты, терабайты в сутки. Списочной цены у них не может быть в принципе, и все проверенные площадки отвечают «цена по запросу»: Positive Technologies, С-Терра, Гарда, InfoWatch, R-Vision, RuSIEM, BI.ZONE, Solar, Zecurion, СёрчИнформ.

Каждая такая позиция помечена `NOT_FOUND` с перечнем проверенных источников — отсутствие цены здесь такой же результат, как её наличие.

Отдельно не засчитаны цифры, которые не удалось подтвердить прямой проверкой страницы: 647 916 ₽ за Eltex ESR-20 (страница закрыта антибот-защитой), 250–300 тыс. ₽ за Security Capsule SIEM (на страницах вендора таких сумм нет), 120 000 ₽ за Dionis-NX (магазин не резолвится), 151 407 и 212 409 ₽ за Diamond VPN/FW. Цифра из поисковой выдачи, которую нельзя открыть и увидеть, в базу не попадает.

Отдельная оговорка по продуктам «Лаборатории Касперского»: многие из них не продаются отдельным SKU, а входят в пакеты (`Kaspersky Endpoint Security для бизнеса`, `Kaspersky Security для почтовых серверов`). Для них указана цена пакета с пометкой `ПАКЕТНАЯ ЦЕНА` в `note` — это не цена конкретного сертифицированного продукта.

## Использование

```bash
curl -L -o szi.sqlite https://raw.githubusercontent.com/velvetway/szi-fstec-mirror/main/data/szi.sqlite
```

Действующие антивирусы не ниже 2 класса защиты:

```sql
SELECT name, applicant, protection_class, valid_until
FROM certificates c
JOIN certificate_controls cc ON cc.certificate_rowid = c.rowid
WHERE cc.control_code = 'A'
  AND c.is_active = 1
  AND c.protection_class <= 2
ORDER BY c.protection_class, c.valid_until DESC;
```

Полнотекстовый поиск:

```sql
SELECT c.name, c.applicant
FROM certificates_fts f
JOIN certificates c ON c.rowid = f.rowid
WHERE certificates_fts MATCH 'касперский OR kaspersky';
```

Что перестанет действовать в ближайший год:

```sql
SELECT name, applicant, valid_until
FROM certificates
WHERE validity_kind = 'dated'
  AND is_active = 1
  AND valid_until <= date('now', '+1 year')
ORDER BY valid_until;
```

## Пересборка

```bash
python scripts/build_db.py --csv data/reg3.csv --db data/szi.sqlite --snapshot-date 2026-08-16
```

Зависимостей нет — только стандартная библиотека Python 3.12.

GitHub Actions пересобирает базу автоматически при изменении `data/reg3.csv` или скрипта сборки.

## Обновление исходника

Реестр отдаётся только с браузерным `User-Agent`, а сертификат сайта подписан УЦ Минцифры:

```bash
curl -k -H "User-Agent: Mozilla/5.0" -H "Referer: https://reestr.fstec.ru/reg3" \
  "https://reestr.fstec.ru/reg3?option=com_rajax&module=rfiles&method=download&format=file&mod=209&file=1" \
  -o data/reg3.csv
```

Флаг `-k` отключает проверку сертификата. Правильнее установить корневой сертификат Минцифры с <https://www.gosuslugi.ru/crt> и обойтись без него.

## Оговорки

- Тип средства и класс защиты **выводятся эвристически** из названия и перечня документов — реестр не публикует их отдельными полями. Для юридически значимых решений сверяйтесь с оригиналом.
- `is_active` вычисляется на дату сборки снапшота, а не на момент запроса.
- Зеркало неофициальное. Первоисточник — сайт ФСТЭК России.
